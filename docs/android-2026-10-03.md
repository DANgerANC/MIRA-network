# MIRA Core 0.1.0 — Android ARM64

> Сохранённые свидетельства обезличены: адреса, имена узлов и фактические локальные пути заменены маркерами. Результаты прежнего запуска сохранены; это не повторная проверка.

3 октября 2026 (Asia/Omsk) ядро собрано для `aarch64-linux-android`
и проверено на физическом телефоне Xiaomi 21081111RG с Android 14.
Все 31 автоматизированная проверка прошла, сценарий завершился с кодом 0.
Изменения Rust-кода не потребовались; контрольные суммы исходников, Web UI
и Cargo.lock совпали с [предыдущим снимком](validation/2026-10-03/source-sha256.json).

## Проверенные действия

CLI, версия, начальный статус, создание папок, пути с кириллицей и пробелами,
относительный путь, MIRA_HOME и приоритет --home работают. Проверены
параллельная запись конфигурации, сохранение настроек и отказ некорректным
значениям без изменения TOML.

HTTP status/version/system совпадают с CLI; встроенные HTML/JS/CSS доступны,
неизвестный маршрут возвращает 404. Второй сервер с той же папкой данных
отклоняется. Смена настроенного порта сохраняет доступ к текущему серверу;
после перезапуска используется новый порт.

SIGTERM и SIGINT завершают процессы MIRA с кодом 0, освобождают блокировку
и записывают события остановки. INFO, DEBUG и ERROR сохранены в журнале.
Повреждённый TOML не затирается.

Системный отчёт вернул aarch64, 8 логических ядер, 7 866 048 512 байт общей
RAM (совпало с /proc/meminfo), диски и сетевые интерфейсы; warnings пуст.
Поле CPU показывает Cortex-A55, а поле os — модель 21081111RG; Android 14
указан в os_version. Это данные текущего сборщика, не полный перечень типов
ядер процессора. Многочисленные Android APEX-монтирования перечисляются
как отдельные диски; их объёмы нельзя суммировать.

Проверки управлялись Python на Windows через ADB. На телефоне выполнялся
Android-бинарный файл MIRA, без установки Python или APK. API слушал loopback
телефона; запросы передавались через временные USB-пробросы портов.
После проверки процессы MIRA остановлены, пробросы удалены. Бинарный файл
и отдельная папка данных сохранены на телефоне:
`[REDACTED_PATH]`.

## Повторение и свидетельства

При установленном локальном Rust и NDK r30:

```powershell
.\build-android.ps1
python tests\android_adb.py target\aarch64-linux-android\release\mira --adb .tools\android\platform-tools\adb.exe --report target\acceptance\android.json
```

Телефон должен быть подключён и разрешён в ADB; при нескольких устройствах
укажите `--serial`. Скрипт создаёт отдельную папку данных для каждого запуска.

## Границы результата

Подтверждена работа проверенного сценария на одном физическом Android ARM64
устройстве в контексте ADB shell. Запуск внутри обычного APK имеет другие
права и ограничения: sandbox приложения, фоновый режим и жизненный цикл
Android здесь не проверены. API 28 выбран при сборке; запуск на Android 9
не выполнялся. Также не проверены Android ARM32/x86, другие телефоны,
отрисовка Web UI в браузере, IPv6 listener, пути по умолчанию и нагрузка.

Вместе с предыдущими проверками подтверждены Windows GNU x86-64,
Linux x86-64, Linux ARM64 в QEMU и Android ARM64 на этом телефоне.
Этот набор результатов не даёт основания утверждать совместимость с 99%
устройств или со всеми ARM-системами.
