# Проверка кроссплатформенности MIRA Core 0.1.0

> Сохранённые свидетельства обезличены: адреса, имена узлов и фактические локальные пути заменены маркерами. Результаты прежнего запуска сохранены; это не повторная проверка.

Нативная release-сборка и общий сценарий CLI/HTTP работают на Windows GNU и
Linux x86-64. Все 59 проверок двух запусков прошли. Ошибок ядра в проверенном
сценарии не обнаружено, изменения Rust-кода не потребовались.

зафиксированы одним `Cargo.lock`. Rust в Linux установлен в отдельную папку
проверки без изменения системного PATH.

## Что проверено

- `--help` и `--version` не создают папку данных; CLI version и status возвращают
  ожидаемые JSON и коды завершения.
- Создание config/data/logs и начальной конфигурации; абсолютный и относительный
  `--home`, пробелы и кириллица в пути; `MIRA_HOME` и приоритет `--home`.
- Архитектура, доступные CPU/RAM, диски и интерфейсы; совпадение неизменяемых
  системных полей между CLI и HTTP.
- Сохранение настроек и параллельные записи разных полей без потери изменения.
- Отказ для порта 0/65536, некорректного адреса, пустого имени и неизвестного
  поля; исходный TOML сохраняется.
- HTTP status/version/system; получение встроенных HTML, JS и CSS; заголовок
  `Cache-Control: no-store`; JSON 404 неизвестного маршрута.
- Отказ второго сервера с той же папкой данных.
- После изменения будущего порта `status` обращается к работающему серверу;
  после перезапуска сервер использует новый порт, настройки сохранены.
- После остановки `status` возвращает stopped с кодом 1, блокировка освобождена.
- Запись INFO/DEBUG/ERROR в файловый журнал.
- Повреждённый TOML вызывает ошибку и не заменяется значениями по умолчанию.
- Дополнительно на Linux: SIGTERM и SIGINT завершают сервер с кодом 0,
  события `Shutdown requested` и `MIRA Core stopped` сохранены в журнале.

## Повторение

Сценарий использует только стандартную библиотеку Python 3.8+ и собственную
папку данных рядом с отчётом. Сборку выполняйте нативно на проверяемой ОС.

Windows PowerShell (Python должен быть доступен в PATH):

```powershell
.\build.ps1
python tests/cross_platform.py target/release/mira.exe --report target/acceptance/windows.json
```

Linux:

```sh
cargo build --release --locked
python3 tests/cross_platform.py target/release/mira --report target/acceptance/linux.json
```

Сценарий возвращает код 0 только при успешном прохождении всех проверок.
JSON содержит результаты, команды, коды выхода, stdout/stderr и системный отчёт.

## Границы результата

Linux ARM64 проверен позднее отдельным запуском:
[отчёт QEMU](arm64-qemu-2026-10-03.md). Он не входит в 59 проверок этого отчёта.
Windows MSVC, macOS, Linux musl и минимальная заявленная версия
Rust 1.88 не проверялись. Результат Linux относится к указанной системе с glibc
2.39, а не ко всем дистрибутивам и версиям glibc.

Этот сценарий проверяет выдачу ресурсов Web UI по HTTP. Отрисовка и переключение
Online/Offline в браузере Linux не проверялись; ранее была отдельная демонстрация
Web UI на Windows. Ctrl+C на Windows также не подтверждён: сценарий там
принудительно завершает только собственные тестовые процессы.

Пути по умолчанию без `--home`/`MIRA_HOME`, IPv6 listener, нагрузка, аварийное
выключение питания и все пункты полной ручной приёмки не проверялись.
Подтверждена переносимость ядра в перечисленном сценарии на обязательных ОС
x86-64; это не заключение о завершении всей приёмки релиза.
