# Приёмка MIRA Core 0.1

26 сентября 2026 выполнена базовая демонстрация на Windows x86-64.
Подтверждённые действия и оставшиеся ограничения: [demo-windows.md](demo-windows.md).
1 и 3 октября 2026 выполнены автоматизированные проверки Windows GNU и Linux
x86-64: [отчёт](cross-platform-2026-10-03.md). 3 октября также прошла
[проверка Linux ARM64 в QEMU](arm64-qemu-2026-10-03.md) и
[Android ARM64 на физическом телефоне через ADB](android-2026-10-03.md).
Полный ручной сценарий ниже ещё
не выполнен на всех целевых платформах; ограничения перечислены в отчёте.

Сценарий запускается нативно на каждой машине. Одна кросс-компиляция не заменяет
запуск на целевой архитектуре. Установите актуальный стабильный Rust и C linker
для нужной платформы. Команды ниже предполагают `mira` в PATH после
`cargo install --path core`; можно использовать полный путь к бинарному файлу.

## Ручной сценарий

1. Из корня репозитория выполните `cargo build --release`. После первой сборки
   сохраните `Cargo.lock`; последующие сборки можно выполнять с `--locked`.
2. В новой отдельной папке данных выполните:

   ```sh
   mira --home ./.mira version
   mira --home ./.mira system
   mira --home ./.mira config
   mira --home ./.mira config paths
   mira --home ./.mira status --json
   ```

   Ожидается версия 0.1.0, правдоподобные сведения текущей ОС и статус stopped
   (код выхода 1). Папки config/data/logs и начальный mira.toml созданы.
3. Измените настройки:

   ```sh
   mira --home ./.mira config set node_name acceptance-node
   mira --home ./.mira config set logging.level debug
   mira --home ./.mira config
   ```

   Новый процесс должен прочитать сохранённые значения.
4. Запустите `mira --home ./.mira serve`, оставьте терминал открытым.
5. Во втором терминале из той же папки выполните
   `mira --home ./.mira status --json`. Ожидается `core: 0.1.0`, `status: ok`, код 0.
   Получите `http://127.0.0.1:8787/api/v1/status` через браузер, `curl` на Linux
   или `Invoke-RestMethod` в PowerShell: значения полей должны совпасть.
6. Откройте `/api/v1/version`, `/api/v1/system` и главную страницу `/`.
   Сравните системные поля с `mira --home ./.mira system --json` и данными ОС.
   Допускается изменение свободной RAM/места между запросами.
7. Убедитесь, что браузер показывает Online, версию, ОС, RAM и IP,
   а через 5 секунд обновляет данные. Посмотрите INFO и DEBUG в файле журнала.
8. Попробуйте второй `serve` с тем же `--home`: ожидается понятная ошибка.
   Попробуйте `config set http.port 0`: ожидается ошибка, TOML не меняется.
9. При работающем сервере сохраните `http.port 9090`. `status` должен продолжить
   получать ответ старого listener. Остановите сервер Ctrl+C и запустите снова:
   сервер и `status` должны использовать порт 9090. node_name и logging.level
   должны сохраниться.
10. Остановите сервер. `status` должен вернуть stopped, открытая страница — Offline
    после очередной попытки обновления. На Linux дополнительно завершите сервер
    сигналом SIGTERM и убедитесь в штатной записи события остановки.
11. При остановленном сервере сохраните копию TOML и внесите синтаксическую ошибку.
    Новая команда должна сообщить об ошибке без затирания файла. Восстановите копию.

Фиксируйте ОС и её версию, архитектуру, версии rustc/cargo, команду, код выхода
и результат. До успешного выполнения на Windows x86-64 и Linux x86-64 релиз
0.1 не следует считать принятым.
