# MIRA Core 0.1.0 — Linux ARM64 в QEMU

> Сохранённые свидетельства обезличены: адреса, имена узлов и фактические локальные пути заменены маркерами. Результаты прежнего запуска сохранены; это не повторная проверка.

3 октября 2026 (Asia/Omsk) ядро успешно собрано для
`aarch64-unknown-linux-gnu` и запущено в полноценной Ubuntu ARM64 под QEMU.
Все 31 проверки общего сценария прошли. Изменения Rust-кода не потребовались.

Это подтверждает работу проверенного сценария в Linux ARM64 в эмуляции.
Проверка на физическом ARM-устройстве, Android и других ARM-ОС не выполнялась.

## Результат выполнения

MIRA сообщила `architecture: aarch64`, CPU `Cortex-A72`, 2 логических и
2 физических ядра, 1 521 180 672 байт доступной ОС общей RAM, три точки
подключения дисков и интерфейсы `enp0s3`/`lo`. Список предупреждений пуст.
Системные поля CLI совпали с HTTP API.

Проверены версия и статусы, создание папок и конфигурации, пути с кириллицей
и пробелами, `MIRA_HOME` и приоритет `--home`, параллельная запись настроек,
отказ некорректным значениям, API status/version/system, встроенные ресурсы
Web UI, 404, блокировка второго сервера, смена порта, сохранение настроек
после перезапуска и защита повреждённого TOML.

SIGTERM и SIGINT завершили именно процессы MIRA с кодом 0. Статус после
остановки — stopped с кодом 1, блокировка освобождена, события завершения
сохранены в файле журнала. INFO, DEBUG и ERROR также записаны.

Кросс-компиляция выполнена на x86-64-хосте, а Python-сценарий и ARM64-бинарный
файл выполнялись внутри гостевой ARM64 ОС. Поэтому системная диагностика
проверена на ARM64-ядре Linux. Сам QEMU после получения результата остановлен
сценарием; его общий тайм-аут остановки не является проверкой выключения Ubuntu.

## Повторение

В Linux x86-64 с установленным Rust/rustup:

```sh
sudo apt-get update
sudo apt-get install -y --no-install-recommends \
  qemu-system-arm qemu-utils qemu-efi-aarch64 cloud-image-utils \
  gcc-aarch64-linux-gnu libc6-dev-arm64-cross
bash tests/arm64_qemu.sh
```

Сценарий скачивает зафиксированный образ, проверяет SHA-256, создаёт отдельный
диск поверх него, выполняет кросс-сборку, загружает ARM64-гостя и запускает
общий сценарий от обычного пользователя. Для повторных запусков образ
кэшируется в `target/qemu-images/20260926`; результаты сохраняются в отдельной
папке `target/arm64-qemu-*`. Нужен доступ к официальным серверам Rust/Ubuntu
при первой подготовке. Порт 18787 на loopback хоста должен быть свободен.

При подготовке выяснилось, что установка GCC без рекомендуемых пакетов
требует явного `libc6-dev-arm64-cross` для линковки. В QEMU отключён ROM
сетевой загрузки (`romfile=`), поскольку используется диск Ubuntu.
Эти настройки включены в [сценарий](../tests/arm64_qemu.sh).
